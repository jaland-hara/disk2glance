# disk2glance

Перенос работающих Linux-ВМ в VK Cloud без остановки приложений.

disk2glance копирует диск виртуальной машины в облако, пока ВМ продолжает работать: агент на
исходной ВМ делает согласованный снимок (снапшот) файловых систем и передаёт данные в целевой
проект. Из полученной копии в облаке создаётся новая ВМ — точная копия исходной на момент
снимка. Проверено на VK Cloud; подходит и для других облаков на OpenStack.

## Как это работает

![Общая схема переноса](docs/img/guide/overview.svg)

1. На исходной ВМ устанавливается агент. Для снимков он использует модуль ядра dattobd:
   приложения продолжают работать, запись на диск приостанавливается лишь на 1–3 секунды.
2. Агент читает диск со снимка и отправляет данные в целевое облако.
3. Из копии в облаке создаётся новая ВМ. При первой загрузке файловые системы и базы данных
   восстанавливаются по своим журналам, как после внезапного отключения питания.

Компилятор, пакеты из репозиториев и вспомогательные ВМ на исходной стороне не нужны: модуль
ядра заранее собран под распространённые ядра и загружается только на время переноса.

Данные можно передавать без интернета — по Direct Connect, VPN или внутренней сети облака: см.
[передачу по частным сетям](docs/network.md).


## Два способа переноса

| | Через оркестратор (рекомендуется) | Только агент |
|---|---|---|
| Что устанавливается | ВМ-оркестратор в целевом проекте; агенты ставятся на исходные ВМ одной командой из веб-интерфейса | агент на каждую исходную ВМ |
| Куда передаётся диск | сразу в том (диск) VK Cloud через приёмник | в образ Glance или объект S3 |
| Повторный перенос | передаются только изменения (дельты), по кнопке или по расписанию | каждый раз весь диск |
| Учётные данные облака | только на оркестраторе | на каждой исходной ВМ |
| Управление | веб-интерфейс и команда `d2g` | командная строка на исходной ВМ |
| Новая ВМ | кнопка «Создать ВМ» | командами `openstack` из образа |
| Перенос в другие проекты | один оркестратор на несколько проектов и регионов | отдельная учётная запись на каждой исходной ВМ |
| Состояние | экспериментально | стабильно |

**Какой выбрать.** Через оркестратор — если ВМ несколько, нужен перенос с минимальным
простоем (дельты) или учётные данные облака не должны попадать на исходные ВМ. Только агент —
для разового переноса одной-двух ВМ без дополнительной инфраструктуры.

## С чего начать

- **Через оркестратор:** [руководство с иллюстрациями](docs/guide.md) — от создания ВМ в VK
  Cloud до новой ВМ из перенесённого диска. Установка одной командой:

  ```bash
  curl -fsSL https://github.com/jaland-hara/disk2glance/releases/latest/download/d2g-server-install.sh | sudo bash
  ```

- **Только агент:** [перенос в Glance по шагам](docs/quickstart.md). Коротко: скопировать
  архив из [Releases](https://github.com/jaland-hara/disk2glance/releases) на исходную ВМ и
  выполнить

  ```bash
  tar xzf disk2glance-0.8.2.tar.gz && cd disk2glance-0.8.2
  sudo ./install.sh                         # создаст /etc/disk2glance/{openrc,props.json,disk2glance.conf}
  sudo vi /etc/disk2glance/openrc           # вписать учётные данные целевого облака
  sudo disk2glance --check                  # проверка без переноса
  sudo disk2glance --detach --name myvm-1   # перенос в фоне, журнал: /var/log/disk2glance.log
  ```

## Поддерживаемые системы

| | |
|---|---|
| Архитектура | x86_64 |
| Файловые системы | ext3, ext4, xfs — на разделах или на линейных томах LVM |
| Проверенные ОС | Ubuntu 22.04 и 24.04, RED OS 7.3 и 8, CentOS 7.9, Astra Linux SE 1.7 и 1.8 |
| Есть готовые модули, проверены снапшоты | AlmaLinux 8.10, 9.8 и 10.2 (с 0.8.2; полный перенос на этих ОС ещё не проверялся) |
| Откуда переносили | VK Cloud (другой проект и другой регион), Яндекс Облако, Cloud.ru |
| С других гипервизоров | VMware, Hyper-V, Xen — после подготовки по [guest-drivers.md](docs/guest-drivers.md) |
| Не поддерживается | Windows, btrfs, mdraid, dm-crypt — см. [limitations.md](docs/limitations.md) |

Подробности проверок — в [test-reports.md](docs/test-reports.md).

## Термины

| Термин | Что это |
|---|---|
| **Исходная ВМ (источник)** | ВМ, которую переносят (в любом облаке или на любом гипервизоре). На ней устанавливается и работает агент. |
| **Целевое облако** | облако OpenStack, куда переносят ВМ (проверено на VK Cloud). |
| **Целевой проект** | проект облака, в котором создаётся новая ВМ: проект оркестратора или другой проект, добавленный на вкладке «Проекты». |
| **Новая ВМ** | ВМ в целевом облаке, созданная из перенесённого диска. Копия исходной ВМ на момент снапшота. |
| **Снапшот** | снимок файловой системы на определённый момент; приложения при этом продолжают работать. |
| **Агент** | программа на исходной ВМ, которая делает снапшоты и передаёт диск. |
| **Оркестратор** | ВМ в целевом проекте: выдаёт агентам сертификаты, создаёт тома и приёмники, ведёт задания, собирает новые ВМ. Управляется через веб-интерфейс и команду `d2g`. |
| **Приёмник** | служба, которая принимает части диска по HTTPS и записывает их в подключённый к ней том. Приёмник `rx0` работает на ВМ оркестратора, остальные — на отдельных ВМ, которые создаёт оркестратор. |
| **Том** | облачный диск (Cinder). Перенесённый диск становится томом, из которого создаётся новая ВМ. |
| **Задание** | перенос одного диска исходной ВМ в один том: том, приёмник, проходы, сборка новой ВМ. |
| **Проход, дельта** | одна передача диска со своего снапшота. Первый проход передаёт все занятые блоки, следующие (дельты) — только изменившиеся. |
| **Образ** | копия всего диска в Glance (вариант «только агент»). |
| **Бандл** | архив `disk2glance-<версия>.tar.gz`: агент, установщик, готовые модули ядра, утилиты. |
| **Модуль dattobd** | модуль ядра Linux для снапшотов без остановки ФС. Собирается под конкретное ядро. |
| **Сборочная ВМ** | вспомогательная ВМ, на которой собирают модули dattobd под новые ядра. В переносе не участвует. |
| **FIP** | плавающий IP-адрес (floating IP) — публичный адрес, назначаемый ВМ в облаке. |
| **Серый адрес** | частный IP-адрес ВМ во внутренней сети проекта; доступен из той же сети или через Direct Connect. |
| **Флейвор (flavor)** | тип ВМ в облаке: число vCPU и объём памяти, например `STD3-4-8`. |

## Состав репозитория

| Путь | Что это |
|---|---|
| `disk2glance.sh` | агент для Glance (`/opt/disk2glance/bin/disk2glance`) |
| `disk2s3.sh`, `s3restore.sh` | агент для S3 и сборка тома из S3 на временной ВМ в целевом облаке |
| `disk2rx.sh` | агент для оркестратора (`/opt/disk2glance/bin/disk2rx`, служба `disk2rx-agent`) |
| `server/` | оркестратор и приёмник `d2g` (Python, только стандартная библиотека), установщик сервера, веб-интерфейс |
| `install.sh` | установщик и деинсталлятор агента |
| `d2g-server-install.sh` | установка оркестратора одной командой из GitHub Releases |
| `make-bundle.sh`, `make-server-bundle.sh` | сборка архивов агента и сервера в `dist/` |
| `publish-release.sh` | публикация релиза в GitHub Releases (токен из `GITHUB_TOKEN`) |
| `build-module.sh`, `modules/`, `patches/` | сборка `dattobd.ko`, готовые модули (dattobd 0.12.2) и доработки dattobd: набор снапшотов, исправление для ядер 6.0+ |
| `bin/` | статические `dbdctl`, `update-img` (dattobd) и `jq` 1.7.1 |
| `setup-testload.sh`, `verify-clone.sh` | тестовая нагрузка на исходной ВМ и проверка данных на новой ВМ |
| `examples/` | шаблоны `openrc`, `disk2glance.conf` и `props.json` для проверенных ОС |
| `tools/guide-shots/` | пересъёмка скриншотов руководства |

Учётные данные в репозиторий не попадают.

## Планы

Windows (VSS, vTPM, BitLocker), Astra Linux с включённой ЗПС (подпись модуля), сборка модулей
в CI, хуки для согласованности приложений (`--pre-snapshot` / `--post-snapshot`), перенос
нескольких дисков за один запуск, вход в интерфейс через SSO. Подробнее — в
[limitations.md](docs/limitations.md).
