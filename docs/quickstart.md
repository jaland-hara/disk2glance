# Перенос агентом в Glance: пошаговое руководство

Руководство по способу «только агент»: агент на исходной ВМ отправляет весь диск в Glance, и
из полученного образа создаётся новая ВМ. Подходит для разового переноса одной-двух ВМ. Для
переноса многих ВМ и переноса с дельтами используйте [оркестратор](guide.md). Справочник по
параметрам и ошибкам — [usage.md](usage.md). Термины — в [README](../README.md#термины), оглавление документации — в [docs/README.md](README.md).

Все команды на исходной ВМ выполняются от root (через `sudo`).

## Шаг 1. Проверить, что исходная ВМ подходит

```bash
uname -r          # ядро: должно быть в списке готовых модулей бандла
lsblk -f          # разделы и файловые системы
```

Подходит, если:
- архитектура x86_64;
- файловые системы ext4, ext3 или xfs, на разделах или на линейных томах LVM;
- ядро есть в списке модулей бандла: [THIRD_PARTY.md](../THIRD_PARTY.md#готовые-модули-в-бандле).
  Если ядра нет, модуль собирают отдельно ([build-modules.md](build-modules.md)).
- исходная ВМ уже работает на KVM (другое облако OpenStack, Yandex Cloud, Proxmox) — тогда
  драйверы готовы. Если она на VMware, Hyper-V или Xen, сначала подготовьте её по
  [guest-drivers.md](guest-drivers.md) (5–10 минут, без перезагрузки);
- с исходной ВМ открыт исходящий HTTPS до API целевого облака (в VK Cloud это
  `infra.mail.ru`, порты 35357 и 9292). Проверка:

  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' https://infra.mail.ru:35357/v3/
  ```

  Ответ `200` означает, что доступ есть.

## Шаг 2. Подготовить данные целевого облака

Понадобятся пять значений (в VK Cloud: личный кабинет → проект → «Доступ по API»):

| Что | Пример | Где взять в VK Cloud |
|---|---|---|
| Адрес Keystone | `https://infra.mail.ru:35357/v3/` | «Доступ по API» |
| ID проекта | `9a9b…` (32 символа) | «Доступ по API» → Project ID |
| Регион | `RegionOne` | «Доступ по API» |
| Пользователь и его домен | `user@example.com`, `users` | «Доступ по API» → Username, User Domain Name |
| Пароль | | пароль этого пользователя |

Доступ по API должен быть включён для пользователя. В VK Cloud он включается на той же
странице.

**Рекомендуется отдельная сервисная учётная запись** для загрузки образов с ролью
«Администратор виртуальных машин» (проверено; «Младший администратор ВМ» образы создавать
не может). Её пароль хранится на исходной ВМ, пока идёт перенос, поэтому создайте её на
время переноса и удалите после. Создавать новые ВМ из образов могут учётные записи групп с
ролью «Младший администратор ВМ». Как создать и какие роли нужны —
[service-accounts.md](service-accounts.md). Для сервисной учётной записи имя пользователя
имеет вид `svc-<ID проекта>-<имя>`, домен — `service-users`.

## Шаг 3. Установить агент

Скопируйте бандл на исходную ВМ одним из способов.

**А. Загрузка с GitHub прямо на исходную ВМ:**

```bash
curl -fsSLO https://github.com/jaland-hara/disk2glance/releases/download/v0.8.1/disk2glance-0.8.1.tar.gz
```

**Б. Без интернета на исходной ВМ:** скачайте `disk2glance-0.8.1.tar.gz` со страницы
[Releases](https://github.com/jaland-hara/disk2glance/releases) на свой компьютер и скопируйте:

```bash
scp disk2glance-0.8.1.tar.gz root@<исходная-ВМ>:/root/
```

Распакуйте и установите:

```bash
tar xzf disk2glance-0.8.1.tar.gz
cd disk2glance-0.8.1
sudo ./install.sh
```

Установщик создаст каталог `/etc/disk2glance` с тремя файлами:

| Файл | Что в нём | Что с ним делать |
|---|---|---|
| `/etc/disk2glance/openrc` | учётные данные целевого облака | **заполнить** (шаг 4) |
| `/etc/disk2glance/props.json` | свойства будущего образа | проверить (шаг 5); установщик подобрал пример под ОС |
| `/etc/disk2glance/disk2glance.conf` | параметры по умолчанию (диск, размер COW) | обычно менять не нужно |

Если какой-то из этих файлов уже существует, установщик его не изменяет.

## Шаг 4. Заполнить учётные данные

```bash
sudo vi /etc/disk2glance/openrc      # или nano
```

Замените значения в угловых скобках данными из шага 2:

```bash
export OS_AUTH_URL="https://infra.mail.ru:35357/v3/"
export OS_PROJECT_ID="<ID проекта>"
export OS_REGION_NAME="RegionOne"
export OS_USERNAME="<имя пользователя>"
export OS_USER_DOMAIN_NAME="<домен пользователя>"
export OS_PASSWORD="<пароль>"
```

Файл должен быть доступен только root (`chmod 600`; установщик задаёт эти права).

> **Если вы скачали openrc из личного кабинета.** В таком файле пароль запрашивается с
> клавиатуры (строки с `read` и `echo "Please enter…"`). Агент работает без участия человека,
> поэтому эти строки нужно удалить и добавить строку `export OS_PASSWORD="..."`. Если оставить
> запрос, агент остановится с подсказкой.

Готовый файл можно не редактировать на месте, а передать установщику:
`sudo ./install.sh --openrc /root/my-openrc` скопирует его в `/etc/disk2glance/openrc`.

## Шаг 5. Проверить свойства образа

```bash
cat /etc/disk2glance/props.json
```

Свойства сообщают целевому облаку, как запускать ВМ из образа: тип ОС, модель сетевой карты,
наличие гостевого агента. Установщик подобрал пример под ОС исходной ВМ (все примеры находятся в
`/opt/disk2glance/examples/`). Что проверить:

- ВМ загружается через **UEFI** (есть каталог `/sys/firmware/efi`)? Тогда добавьте
  `"hw_firmware_type": "uefi"` и `"hw_machine_type": "q35"`.
- На исходной ВМ **нет** `qemu-guest-agent` (`systemctl status qemu-guest-agent`)? Тогда
  уберите строку `"hw_qemu_guest_agent": "yes"`.

## Шаг 6. Проверка без переноса

```bash
sudo disk2glance --check
```

Агент проверит файлы конфигурации, вход в облако, разметку диска, загрузку модуля,
готовность гостевой ОС к KVM и право учётной записи создавать образы (создаст и сразу удалит
пустой тестовый образ), но ничего не скопирует. Пример успешной проверки:

```
credentials: /etc/disk2glance/openrc; image properties: /etc/disk2glance/props.json (...)
auth OK, Glance https://infra.mail.ru:9292
  /dev/vda1 start=1048576 size=21473771008 fs=ext4 mnt=/ -> snap
dattobd 0.12.2 loaded
guest: hypervisor now: kvm (target: KVM, virtio devices)
guest: OK for KVM (virtio drivers available at boot, fstab by UUID/LABEL)
permissions: image create/delete in Glance OK
CHECK OK: image would be 21474836480 bytes raw
```

Если есть строки `WARN` про гостевую ОС, итог будет `CHECK OK, BUT ...`: исправьте их по
[guest-drivers.md](guest-drivers.md), иначе новая ВМ может не загрузиться. Если нет права
создавать образы — см. [service-accounts.md](service-accounts.md).

Если вместо этого выведено `ERROR: …`, в сообщении указано, что требуется исправить (например, какая
переменная не задана в openrc). Разбор ошибок есть в [usage.md](usage.md#ошибки-и-их-устранение).

## Шаг 7. Перенос

```bash
sudo disk2glance --detach --name myvm-2026-10-16
```

- `--name` задаёт имя образа в целевом облаке. Без него имя будет `<hostname>-<дата-время>`.
- `--detach` запускает перенос в фоне отдельной системной службой. SSH-сессию можно закрыть,
  перенос продолжится. На Astra Linux это обязательно.

Следить за ходом:

```bash
tail -f /var/log/disk2glance.log
```

Перенос закончен, когда в логе появилось:

```
upload done in 262 s (78 MiB/s): status=active size=21474836480
OK: size and md5 match Glance
6a8a45e5-bac7-4d93-b6ba-f3eabf2a7baf        ← ID образа в целевом облаке
```

Время зависит от размера диска (передаётся весь диск, включая пустое место) и сети. В VK
Cloud ориентир 3–5 минут на 20 ГБ. Приложения на исходной ВМ всё это время работают; при
создании снапшота запись на диск на 1–3 секунды приостанавливается.

Прервать перенос: `sudo systemctl stop disk2glance-<дата-время>` (имя службы есть в первой
строке, которую вывела команда запуска). Снапшоты агент удаляет при остановке.

## Шаг 8. Создать новую ВМ в целевом облаке

Образ появится в проекте под именем из `--name`. Создайте из него ВМ.

**В личном кабинете VK Cloud:** откройте список образов проекта, найдите образ по имени
и создайте из него виртуальную машину. Размер диска укажите не меньше размера диска
исходной ВМ.

**Через OpenStack CLI:**

```bash
openstack server create myvm --image <ID образа> --flavor <тип ВМ> \
  --boot-from-volume <размер диска, ГБ> --network <сеть> \
  --security-group <группа> --key-name <ключ>
```

При первой загрузке новая ВМ восстанавливает файловые системы и базы данных по журналам;
на медленных дисках это может занять несколько минут. Службы исходной ВМ запускаются и на
новой ВМ.

## Шаг 9. Удалить агент

На исходной ВМ и на новой ВМ (агент скопирован туда вместе с диском):

```bash
sudo /opt/disk2glance/install.sh --uninstall --purge
```

`--purge` удаляет и `/etc/disk2glance` вместе с паролем. Без него конфигурация остаётся для
следующего запуска.

## Расположение файлов

По умолчанию агент читает файлы из `/etc/disk2glance/`, поэтому в простом случае указывать
пути не нужно. Если файлы находятся в другом месте или их несколько (например, перенос в разные
проекты), пути передаются параметрами:

```bash
sudo disk2glance --check  --openrc /root/projectA.openrc --props /root/props-uefi.json
sudo disk2glance --detach --openrc /root/projectA.openrc --props /root/props-uefi.json --name myvm-A
```

Параметры можно также собрать в отдельном файле и указать его:

```bash
cat /root/projectA.conf
OPENRC=/root/projectA.openrc
PROPS=/root/props-uefi.json
DISK=/dev/vda
COW_MB=512

sudo disk2glance --detach --config /root/projectA.conf --name myvm-A
```

Приоритет: параметры командной строки имеют приоритет над файлом параметров, файл
параметров — над значениями по умолчанию.


| Что | По умолчанию | Как указать другое |
|---|---|---|
| учётные данные | `/etc/disk2glance/openrc` | `--openrc FILE` или `OPENRC=` в файле параметров |
| свойства образа | `/etc/disk2glance/props.json` | `--props FILE` или `PROPS=` |
| файл параметров | `/etc/disk2glance/disk2glance.conf` | `--config FILE` |
| диск | `/dev/vda` | `--disk /dev/vdb` или `DISK=` |
| размер COW | 10% тома | `--cow-mb N` или `COW_MB=` |
| лог (с `--detach`) | `/var/log/disk2glance.log` | — |
